Installer des paquets Python pour les add-ons Blender (Windows, Blender 4.2+)

Sylvie : Tu écris un add-on Blender qui a besoin de NumPy. Tu tapes pip install, et Blender répond qu'il ne connaît pas le module. Qu'est-ce qui se passe ?

Thierry : J'aurais blâmé pip. Quelle est la vraie raison ?

Sylvie : Blender embarque son propre Python. Le pip de ton système installe pour un tout autre interpréteur. Antoine a donc écrit un petit installateur qui parle directement au Python de Blender.

Thierry : Comment il le trouve ?

Sylvie : Dans Blender, l'exécutable système pointe vers l'interpréteur fourni avec Blender. Le script lance pip par ce biais, donc les paquets sont installés pour le Python qui fera réellement l'import. Ça marche sous Windows, avec Blender 4.2 et plus.

Thierry : Et les paquets, ils vont où ?

Sylvie : Dans un dossier de modules propre à l'utilisateur, que Blender sait nommer. Pas besoin de droits administrateur, et il survit au rechargement de l'add-on. Le script ajoute ensuite ce dossier au chemin d'import, et l'import suivant fonctionne.

Thierry : C'est comme un livreur qui passe toujours par la porte de service de l'immeuble, pas par la réception d'un autre bâtiment.

Sylvie : Bien vu. Et les téléchargements ? Blender ne se fige pas ?

Thierry : Deuxième astuce : l'installation tourne dans un thread d'arrière-plan, avec une barre de progression, donc l'interface reste fluide. Seule la boucle principale peut toucher l'interface, alors les fenêtres passent par un minuteur de Blender. À la fin, un message te prévient.

Sylvie : Il réinstalle tout à chaque fois ?

Thierry : Non. Il tente d'abord l'import de chaque paquet et saute ceux qui existent déjà, donc la deuxième exécution est rapide. La liste tient dans un seul dictionnaire, avec des versions épinglées, par exemple pour meshio et requests.

Sylvie : Et pour l'utiliser ?

Thierry : Deux façons. Tu le colles dans l'espace Scripting, tu cliques sur Run Script et tu attends la fenêtre de confirmation. Ou tu l'appelles depuis la fonction register de l'add-on, pour que les dépendances arrivent avec lui, sans que personne ait à deviner quel Python utiliser.

Sylvie : Moins de courriels de support, donc.

Thierry : Exactement. Tout est maîtrisé depuis une seule liste. L'article complet a le script en entier et une capture de l'espace Scripting, si tu veux le copier.

Les add-ons Blender qui ont besoin de NumPy, meshio ou requests butent tous sur le même mur : Blender embarque son propre Python, donc le pip du système ne sert à rien. J’ai écrit un petit installateur qui cible le sys.executable de Blender, dépose les paquets dans scripts/modules et tourne dans un thread d’arrière-plan pour que l’interface reste réactive (Blender 4.2+, Windows).

1. Le problème en une phrase

Un pip install global ne rend pas import meshio disponible dans Blender : l’interpréteur est celui fourni avec Blender.

2. La stratégie

ÉlémentRôle
sys.executableLancer pip avec le Python de Blender
bpy.utils.user_resource("SCRIPTS", path="modules")Dossier d’installation accessible en écriture, par utilisateur et par version
site.addsitedirRendre les imports résolubles
Thread d’arrière-plan + bpy.app.timersNe pas figer l’interface ; afficher une fenêtre à la fin

3. Le script d’installation

import bpy
import sys
import site
import logging
import subprocess
import threading

# Set up logging
logger = logging.getLogger(__name__)
logging.basicConfig(level=logging.INFO)

# List of packages required by the add-on/plugin
REQUIRED_PACKAGES = {
    "fileseq": "fileseq==1.15.2",
    "meshio": "meshio==5.3.4",
    "rich": "rich==13.7.0",
    "requests": "requests==2.31.0"
}

def get_blender_python_path():
    """Returns the path of Blender's embedded Python interpreter."""
    return sys.executable

def get_modules_path():
    """Return a writable directory for installing Python packages."""
    return bpy.utils.user_resource("SCRIPTS", path="modules", create=True)

def append_modules_to_sys_path(modules_path):
    """Ensure Blender can find installed packages."""
    if modules_path not in sys.path:
        sys.path.append(modules_path)
    site.addsitedir(modules_path)

def display_message(message, title="Notification", icon='INFO'):
    """Show a popup message in Blender."""
    def draw(self, context):
        self.layout.label(text=message)
    def show_popup():
        bpy.context.window_manager.popup_menu(draw, title=title, icon=icon)
        return None  # Stops timer
    bpy.app.timers.register(show_popup)

def install_package(package, modules_path):
    """Install a single package using Blender's Python."""
    try:
        logger.info(f"Installing {package}...")
        subprocess.check_call([
            get_blender_python_path(),
            "-m",
            "pip",
            "install",
            "--upgrade",
            "--target",
            modules_path,
            package
        ])
        logger.info(f"{package} installed successfully.")
    except subprocess.CalledProcessError as e:
        logger.error(f"Failed to install {package}. Error: {e}")
        display_message(f"Failed to install {package}. Check console for details.", icon='ERROR')

def background_install_packages(packages, modules_path):
    """Install missing packages in a background thread."""
    def install_packages():
        wm = bpy.context.window_manager
        wm.progress_begin(0, len(packages))
        for i, (module_name, pip_spec) in enumerate(packages.items()):
            try:
                __import__(module_name)
                logger.info(f"'{module_name}' is already installed.")
            except ImportError:
                install_package(pip_spec, modules_path)
            wm.progress_update(i + 1)
        wm.progress_end()
        display_message("All required packages installed successfully.")
    threading.Thread(target=install_packages, daemon=True).start()

# Setup
modules_path = get_modules_path()
append_modules_to_sys_path(modules_path)

# Start package installation
background_install_packages(REQUIRED_PACKAGES, modules_path)

Quatre détails font tout le travail :

  • Dans Blender, sys.executable est l’interpréteur de Blender : pip installe donc pour le Python qui fera l’import.
  • --target écrit dans le dossier utilisateur scripts/modules, accessible sans droits administrateur et conservé quand l’add-on est rechargé.
  • La vérification __import__ saute les paquets déjà importables ; une deuxième exécution est rapide.
  • Les fenêtres passent par bpy.app.timers, car seule la boucle principale peut toucher l’interface, pas le thread d’installation.

4. Comment l’exécuter

Option A — espace Scripting : coller le script dans l’éditeur de texte → Run Script → attendre la fenêtre de confirmation.

Option B — dans le register() d’un add-on :

def register():
    modules_path = get_modules_path()
    append_modules_to_sys_path(modules_path)
    background_install_packages(REQUIRED_PACKAGES, modules_path)

Livrez les dépendances avec l’add-on : les utilisateurs n’ont plus à deviner quel Python utiliser.

5. Dépannage

  • Redémarrer Blender après la première installation.
  • print(sys.path) si un import échoue, pour vérifier que modules figure dans la liste.
  • Épingler les versions : le Python de Blender n’est pas le 3.12 de votre système.

6. Quand ne pas utiliser ce modèle

CasPourquoi
L’add-on vise beaucoup de versions de BlenderÉpingler et tester par version mineure
Piles CUDA lourdesPeuvent dépasser la configuration GPU et pilotes de l’utilisateur
Postes d’entreprise verrouilléspip peut être bloqué ; fournir les wheels à la main

7. À retenir

Automatisez l’installation des dépendances dans le bac à sable de Blender. Les utilisateurs arrêtent de demander « quel Python ? », et c’est vous qui maîtrisez la liste dans REQUIRED_PACKAGES.
