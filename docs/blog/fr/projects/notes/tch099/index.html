TCH099 : Un routeur PHP pour les pages et l’API

TCH099 est un projet pédagogique qui combine pages frontend statiques et API PHP. Les routes exposent la frontière: certains chemins retournent du HTML, tandis que d’autres appellent des scripts serveur.

4. Fonctions et composants 2

Routes des pages
routes.php charge router.php, associe accueil et connexion aux fichiers frontend et définit les pages 403 et 404. Le callback /admin vérifie explicitement isAdmin avant de choisir la réponse.
Scripts API
Connexion, inscription, déconnexion et user_details ont leurs scripts API. Des routes de démonstration incluent une langue et une image aléatoire. Les scripts traitent les requêtes; le routeur choisit leur destination.

7. API HTTP et permissions

routes.php associe les chemins ci-dessous. Le README montre des chemins comme /api/login.php et des messages en français. Les gestionnaires utilisent les chemins de ce tableau et des messages en anglais. La colonne d’accès indique un contrôle trouvé dans le gestionnaire.

Contrôles d’accès lus dans les gestionnaires. Une mention « admin » dans le README ne figure ici que si le code la vérifie.
MéthodeCheminContrôle vérifiéFichier
POST/api/loginAucun contrôle de session. loginUser vérifie l’empreinte du mot de passe.api/login.php
POST/api/signupAucun contrôle de session. Le rôle du corps doit être admin ou client, y compris admin pour un nouveau compte.api/signup.php
POST/api/logoutAucun contrôle de session. Le gestionnaire détruit la session.api/logout.php
GET/api/user_detailsExige la clé de session user_loggedin. Le rôle n’est pas vérifié.api/user_details.php
GET/api/clientsExige user_loggedin et le rôle de session admin. Sinon le JSON dit Access denied.api/clients.php
GET/adminPage, pas du JSON. isAdmin() inclut admin.html, sinon 403.html.routes.php
GET, POST/api/hello-world/$langueAucun contrôle de session. Une session connectée remplace prenom par le nom d’utilisateur.api/hello-world.php
GET, POST/api/random-imageAucun contrôle de session dans le gestionnaire.api/random-image.php

7.1. Réponse et erreurs

  • Succès : api/login.php retourne status: success, message: Login successful et redirect: /home.
  • Identifiants invalides : le corps JSON contient status: error et Invalid username or password.
  • Autres méthodes HTTP : le corps JSON contient Invalid request method.
  • Langue des messages : le gestionnaire utilise l’anglais, tandis que les exemples du README sont en français.
  • Détails de session : GET /api/user_details exige user_loggedin et retourne user_details depuis la session.
  • Liste des clients : GET /api/clients exige aussi le rôle admin. Sa requête SELECT * FROM Clients inclut la colonne du mot de passe dans une réponse réussie.
  • Démonstrations publiques : les requêtes GET et POST vers /api/hello-world/$langue et /api/random-image n’ont pas de contrôle de session. Hello World utilise le nom de session pour prenom lorsqu’il existe.
  • Image aléatoire : imageType: human retourne l’URL thispersondoesnotexist.com. Toute autre valeur appelle The Cat API.
Authentification, limites et pagination

POST /api/signup accepte le rôle admin ou client dans le JSON. signup.php n’exige pas une session administrateur avant d’enregistrer ce rôle. router.php envoie Access-Control-Allow-Origin: *. Ces gestionnaires ne fixent pas de limite de débit. GET /admin est une page: routes.php appelle isAdmin() et inclut sinon 403.html. La connexion ne définit pas de statut HTTP d’erreur; l’échec reste dans le JSON.

13. Glossaire

Dépôt

Les fichiers source, la configuration et l’historique versionné d’un projet.

README

Le document d’entrée du dépôt, qui présente généralement son rôle et son installation.

Dépendance

Une bibliothèque, un outil ou un service nécessaire à la compilation ou à l’exécution d’un composant.

API

Une interface par laquelle des composants logiciels échangent des requêtes et des résultats. Une API n’utilise pas nécessairement HTTP.

HTTP

Un protocole de requête et réponse utilisé par les navigateurs et services web. Une requête comprend une méthode, un chemin, des en-têtes et parfois un corps.

Session

Un état conservé entre plusieurs requêtes, souvent pour suivre un utilisateur connecté. L’authentification et les permissions restent des vérifications distinctes.

Conteneur

Un environnement de processus isolé créé à partir d’une image. Les données persistantes nécessitent un stockage hors de son système de fichiers temporaire.

Port publié

Un port de l’hôte associé au port d’un service dans un conteneur. Sa publication peut rendre le service accessible hors du réseau des conteneurs.

Interface en ligne de commande

Une interface textuelle où les commandes et arguments choisissent les opérations. Les codes de retour permettent aux scripts de détecter un succès ou un échec.

Compilation

Les étapes qui transforment les sources et dépendances en programme exécutable ou en livrable distribuable.

Webhook

Une requête HTTP envoyée à un autre système lors d’un événement. Le destinataire doit valider la requête avant de la traiter.
