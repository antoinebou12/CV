kroki-playground : Un éditeur, une API et un moteur de rendu

kroki-playground est une interface Next.js pour modifier des diagrammes textuels et prévisualiser leur rendu. Sa route serveur valide le type et le format, encode la source et récupère le résultat auprès de Kroki.

2. Cas d’utilisation

Un bac à sable Next.js pour écrire du code de diagramme Kroki, voir le SVG en direct et le partager par l’URL.

Prévisualiser un diagramme
Auteur de diagrammesServeur Kroki

DiagramGenerator.tsx compresse la source avec encodeDiagramPayload() (pako, base64url) et charge <base>/<type>/svg/<encodé> depuis kroki.io ou NEXT_PUBLIC_KROKI_BASE_URL.

Changer de type de diagramme
Auteur de diagrammes

lib/kroki/diagramTypes.ts liste les routes Kroki (plantuml, mermaid, graphviz, d2, vega-lite…) proposées dans le sélecteur de type.

Partager ou télécharger
Auteur de diagrammes

La page inscrit ?type=…&source=… dans l’historique, peut copier l’URL Kroki dans le presse-papiers et enregistre l’image sous diagram.svg.

Rendre via l’API REST
Développeur client APIServeur Kroki

app/api/generate-diagram/route.ts accepte GET ou POST avec diagramSource, selectedDiagram et outputFormat et renvoie diagramData en base64 ; le README et openapi.yaml nomment le chemin /api/generateDiagram.

Consulter la doc OpenAPI
Développeur client API

/api-docs affiche public/openapi.yaml avec swagger-ui-react, et GET /api/openapi sert la spécification.

2.1. Scénario : Esquisser un diagramme de séquence et l’envoyer à un collègue

  1. Lancer npm install puis npm run dev et ouvrir http://localhost:3000.
  2. Choisir plantuml dans la liste des types et coller la source @startuml … @enduml.
  3. L’aperçu SVG se met à jour depuis Kroki à mesure que la source change.
  4. Copier l’URL de la page, qui porte maintenant ?type=plantuml&source=<encodé>, et l’envoyer.
  5. Cliquer sur télécharger pour enregistrer diagram.svg dans le document de conception.

6. Fonctions et composants 2

Validation avant le rendu
app/api/generate-diagram/route.ts traite GET et POST avec une validation commune. encodeDiagramPayload prépare la source pour le lien Kroki. KROKI_BASE_URL choisit le service de rendu côté serveur.
Réponse et états d’échec
La route lit les octets reçus et retourne diagramUrl, diagramData en base64 et mimeType. Une erreur HTTP de Kroki devient une réponse 502 avec un code d’erreur externe, distincte d’une entrée invalide.

9. API HTTP de diagrammes

Le fichier de route définit GET et POST /api/generate-diagram. POST lit du JSON; GET lit les mêmes champs dans les paramètres de requête. Le gestionnaire valide le type et le format, compresse la source UTF-8 avec DEFLATE, l’encode pour une URL et appelle le moteur Kroki choisi.

Exemple de requête
POST /api/generate-diagram
Content-Type: application/json

{
  "selectedDiagram": "mermaid",
  "diagramSource": "flowchart LR\n  Client --> Server",
  "outputFormat": "svg"
}

9.1. Réponse et erreurs

Une réponse JSON réussie contient diagramUrl, diagramData (octets en base64) et mimeType. Décodez diagramData avec mimeType pour afficher le résultat. La réponse n’est pas un SVG brut.
HTTP 400 couvre MISSING_DIAGRAM_TYPE, INVALID_DIAGRAM_TYPE, SOURCE_TOO_LARGE et INVALID_OUTPUT_FORMAT. Une erreur HTTP de Kroki devient 502 KROKI_UPSTREAM_ERROR avec upstreamStatus; une exception devient 500 INTERNAL_ERROR. Pour une 502, inspectez le format choisi et la réponse Kroki avant de réessayer. Testez un petit graphe sur un déploiement local.
Authentification, limites et pagination

La route inspectée ne contient ni authentification, ni pagination, ni limiteur de débit. Un proxy de déploiement peut imposer ses propres règles. La source est limitée à 512 000 caractères. KROKI_BASE_URL configure les requêtes serveur; NEXT_PUBLIC_KROKI_BASE_URL configure les aperçus du navigateur. Le README mentionne /api/generateDiagram, tandis que ce fichier définit la route avec trait d’union.
