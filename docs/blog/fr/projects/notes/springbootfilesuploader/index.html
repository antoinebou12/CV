SpringBootFilesUploader

SpringBootFilesUploader est une API REST en Kotlin construite sur Spring Boot 2.6.3. Son nom décrit sa première tâche : recevoir un fichier, en placer les octets dans un compartiment compatible S3 et sa description dans MongoDB, puis le resservir par son identifiant. Le code va plus loin que le nom. La même application liste et contrôle des conteneurs Docker, interroge un serveur Caddy et exécute des commandes par SSH, le tout derrière une authentification JWT à trois rôles. Le dernier commit date de février 2022 et le README tient en une ligne : tout ce qui suit vient du code source.

1. Aperçu

Six contrôleurs composent l’API. Les chemins partent de la racine du serveur ; /auth/** et la documentation de l’API sont publics, tout le reste exige un jeton porteur (SecurityConf.kt).

ContrôleurPoints d’accèsRôles dans @PreAuthorize
AuthController (/auth)POST /signin, POST /signup, POST /signup/adminpublics ; /signup/admin exige ADMIN
FilesController (/files)POST /documents (champ multipart document), GET /{id}envoi : MODERATOR ou ADMIN ; téléchargement : tout rôle
UserController (/user)GET /{id}/page, GET /profile, GET /mod, GET /adminselon le point d’accès
DockerController (/containers)GET /ping, GET /list, PUT /create, POST /start/{name}, /stop/{name}, /restart/{name}, /rename/{name}/{newName}MOD ou ADMIN ; création et renommage ADMIN
CaddyController (/caddy)GET /pingauthentifié
SSHController (/ssh)POST /cliADMIN

La page OpenAPI est servie par springdoc à /api-docs (application.yml).

2. Cas d’utilisation

API Spring Boot en Kotlin qui range les fichiers téléversés dans MinIO/S3 derrière des rôles JWT, avec des routes Docker et SSH.

S'inscrire et obtenir un JWT
Utilisateur de l'APIMinIO S3 et MongoDB

POST /auth/signup enregistre l'utilisateur dans MongoDB avec son mot de passe haché et ses rôles ; POST /auth/signin renvoie un JwtResponse avec le jeton et les rôles (AuthController.kt, JwtUtils.kt).

Téléverser un document
Modérateur ou adminMinIO S3 et MongoDB

POST /files/documents (modérateur ou admin) valide l'extension avec DOC_FILE_EXTENSION_REGEX, écrit le fichier dans le bucket S3 sous files/<uuid>/<nom> et note ses métadonnées dans MongoDB.

Télécharger un fichier stocké
Utilisateur de l'APIMinIO S3 et MongoDB

GET /files/{id} retrouve la fiche du fichier dans MongoDB, lit l'objet dans S3 et le renvoie en pièce jointe avec son type et sa taille.

Gérer des conteneurs Docker
Modérateur ou admin

Les routes /containers listent, créent, démarrent, arrêtent, redémarrent et renomment des conteneurs avec docker-java, sur l'hôte Docker défini dans application.yml (tcp://127.0.0.1:2375).

Lancer une commande SSH
Modérateur ou admin

POST /ssh/cli (admin seulement) ouvre une session Apache SSHD avec l'hôte, le port et les identifiants reçus, puis renvoie la sortie de la commande.

2.1. Scénario : Déposer un PDF puis le récupérer

  1. Démarrer MongoDB sur localhost:27017 et MinIO sur localhost:9000, comme le prévoit application.yml, puis lancer ./gradlew bootRun.
  2. Envoyer POST /auth/signup avec un nom d'utilisateur, un courriel, un mot de passe et le rôle « mod ».
  3. Appeler POST /auth/signin et copier le JWT de la réponse.
  4. Envoyer le PDF à POST /files/documents dans le champ multipart « document » avec le jeton Bearer ; la réponse donne fileId et fileName.
  5. Appeler GET /files/{fileId} pour télécharger le PDF, ou parcourir les routes dans Swagger UI à /api-docs.

3. Parcours d’un envoi

sequenceDiagram
  participant C as Client
  participant F as Filtre JWT
  participant FC as FilesController
  participant FS as FilesService
  participant S3 as FileS3 (S3 / MinIO)
  participant M as FilesMongo (MongoDB)
  C->>F: POST /files/documents, jeton Bearer, multipart "document"
  F->>FC: utilisateur authentifié avec ses rôles
  FC->>FC: @PreAuthorize MODERATOR ou ADMIN, contrôle de l’extension
  FC->>FS: addDocument(octets, nom, ext, contentType, taille)
  FS->>S3: putObject(compartiment "fus", "files/{uuid}/{nom}")
  FS->>M: getNewFileId() = nombre + 1, enregistre FileModel
  FS-->>C: 200 {fileId, fileName}
  C->>FC: GET /files/{fileId}
  FC->>M: getFile(id) → chemin, nom, type, taille
  FC->>S3: getObject(chemin)
  FC-->>C: octets avec Content-Disposition attachment
  1. AuthTokenFilter lit le jeton porteur, JwtUtils le valide avec le jwtSecret de la configuration, et les rôles de l’utilisateur viennent de MongoDB.
  2. FilesController.addDocument refuse une partie manquante et vérifie le nom de fichier avec DOC_FILE_EXTENSION_REGEX : tableurs, documents Word, PDF, images courantes, MP4, MOV, ZIP, MP3, WAV, ISO et RAR. Seule l’extension est vérifiée, pas le contenu. Le contrôle de taille est en commentaire.
  3. FilesService.addDocument construit la clé d’objet files/{UUID aléatoire}/{nom d’origine} et écrit les octets par l’interface FileRepository, implémentée par FileS3 avec le SDK AWS. FileS3 crée le compartiment au démarrage s’il n’existe pas.
  4. Le service demande ensuite un identifiant à FilesMongo, qui vaut le nombre de documents de la collection plus un, puis enregistre un FileModel (identifiant, chemin, nom, extension, UUID, type de contenu, taille).
  5. Un téléchargement cherche l’identifiant dans MongoDB, lit l’objet à son chemin enregistré et le renvoie avec le type et la longueur conservés.

Les octets sont écrits avant les métadonnées. Si l’enregistrement MongoDB échoue, l’objet reste dans le compartiment sans rien qui pointe vers lui.

7. Démarrage

Démarrez MongoDB et MinIO en local (le docker-compose.yml du dépôt est vide), puis lancez l’application avec le profil local, que application.yml active par défaut :

docker run -d -p 27017:27017 mongo
docker run -d -p 9000:9000 -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin minio/minio server /data
./gradlew bootRun

Le profil local pointe aussi vers un serveur Spring Cloud Config sur le port 8888. Les rôles sont lus dans la collection de rôles de MongoDB et rien dans le code ne les crée : insérez ROLE_USER, ROLE_MODERATOR et ROLE_ADMIN avant de vous inscrire.

8. Limites

  • Rôle de modérateur en libre-service. POST /auth/signup transforme un rôle demandé "mod" en ROLE_MODERATOR : n’importe qui peut créer un compte autorisé à envoyer des fichiers.
  • Des noms de rôles qui ne correspondent jamais. DockerController vérifie hasRole('MOD'), mais les rôles sont ROLE_USER, ROLE_MODERATOR et ROLE_ADMIN ; seuls les administrateurs passent ces contrôles.
  • Identifiants séquentiels et concurrents. getNewFileId() renvoie le nombre de documents plus un : deux envois simultanés peuvent obtenir le même identifiant, et une suppression fait entrer le suivant en collision.
  • Envois sans limite, en mémoire. Les limites multipart sont fixées à 500 000 Mo, le contrôle de taille est en commentaire et document.bytes charge tout le fichier en mémoire avant l’envoi vers S3.
  • Exécution de commandes à distance, par conception. /ssh/cli ouvre un shell sur n’importe quel hôte et y exécute la commande donnée pour un administrateur, et /containers parle à un socket TCP Docker sans authentification.
  • Valeurs par défaut versionnées. jwtSecret: secret, les clés MinIO minioadmin, un mot de passe du serveur de configuration et une adresse courriel personnelle se trouvent dans les fichiers YAML.
  • Build et documentation. Le Dockerfile copie project-0.0.2.jar alors que le build produit la version 0.0.3, le fichier Compose et le README sont vides, et le seul test vérifie que le contexte se charge.

13. Glossaire

Dépôt

Les fichiers source, la configuration et l’historique versionné d’un projet.

README

Le document d’entrée du dépôt, qui présente généralement son rôle et son installation.

Dépendance

Une bibliothèque, un outil ou un service nécessaire à la compilation ou à l’exécution d’un composant.

API

Une interface par laquelle des composants logiciels échangent des requêtes et des résultats. Une API n’utilise pas nécessairement HTTP.

HTTP

Un protocole de requête et réponse utilisé par les navigateurs et services web. Une requête comprend une méthode, un chemin, des en-têtes et parfois un corps.

Session

Un état conservé entre plusieurs requêtes, souvent pour suivre un utilisateur connecté. L’authentification et les permissions restent des vérifications distinctes.

Conteneur

Un environnement de processus isolé créé à partir d’une image. Les données persistantes nécessitent un stockage hors de son système de fichiers temporaire.

Docker Compose

Un format de configuration et un outil pour lancer des conteneurs, réseaux et volumes associés. L’ordre de démarrage ne garantit pas qu’un service est prêt.

Volume et montage de dossier

Un volume est un stockage géré par la plateforme de conteneurs ; un montage de dossier expose un chemin de l’hôte dans un conteneur.

Port publié

Un port de l’hôte associé au port d’un service dans un conteneur. Sa publication peut rendre le service accessible hors du réseau des conteneurs.

Interface en ligne de commande

Une interface textuelle où les commandes et arguments choisissent les opérations. Les codes de retour permettent aux scripts de détecter un succès ou un échec.

Compilation

Les étapes qui transforment les sources et dépendances en programme exécutable ou en livrable distribuable.

Mermaid

Un langage de diagrammes textuel. Les nœuds et liens décrivent un modèle ; le diagramme n’exécute pas le projet.

Maillage

Une surface représentée par des sommets et des éléments reliés, souvent des triangles. Sa géométrie est distincte de son matériau ou de sa texture.

Détection continue des collisions

Une recherche de contact pendant le mouvement entre deux états, au lieu de tester seulement ses extrémités.

Backend

Une implémentation derrière une interface commune. Selon le contexte, il peut s’agir d’un service côté serveur ou d’une implémentation graphique, d’entrée ou de stockage.

Base de données

Un système de stockage et d’interrogation de données structurées. Son schéma, ses règles d’accès et sa persistance déterminent comment l’application utilise ces données.

Micrologiciel

Un logiciel exécuté sur un appareil ou microcontrôleur pour contrôler son matériel et ses communications.
