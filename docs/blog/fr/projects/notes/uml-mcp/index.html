uml-mcp

uml-mcp est un serveur Model Context Protocol qui permet à un assistant IA de dessiner des diagrammes. L’assistant écrit la source du diagramme (PlantUML, Mermaid, D2, Graphviz, C4, BPMN …), appelle un des outils du serveur et reçoit une image, un lien vers le fichier rendu et un lien vers un éditeur en ligne. Dans les clients qui prennent en charge les MCP Apps, le diagramme s’ouvre dans une visionneuse au sein de la conversation. Le paquet est publié sur PyPI sous le nom uml-mcp (version 1.4.0 dans pyproject.toml), tourne comme point d’accès hébergé sur Vercel et s’auto-héberge avec Docker ou Helm.

Sylvie : Vous écrivez une phrase dans une conversation, par exemple « dessine un diagramme de séquence d’un utilisateur qui se connecte par une passerelle d’API », et un diagramme tout fini apparaît dans la discussion. Comment ça marche ?

Thierry : J’aurais pensé que l’IA dessine simplement une image. Ce n’est pas ça ?

Sylvie : Pas tout à fait. L’assistant écrit le diagramme sous forme de texte, dans une notation comme PlantUML, Mermaid ou D2. Puis il appelle un outil, et cet outil, c’est uml-mcp, un serveur Model Context Protocol. Il renvoie une image, un lien vers le fichier rendu et un lien vers un éditeur en ligne.

Thierry : Donc l’IA écrit la recette et le serveur fait la cuisine.

Sylvie : Bien dit. Dans les clients qui prennent en charge les MCP Apps, le diagramme s’ouvre même dans une visionneuse au cœur de la conversation. Dans la démo, un seul appel par lot renvoie quatre diagrammes sous forme d’onglets, et on passe de l’un à l’autre ou on refait le rendu dans un autre format.

Thierry : Il y a combien de sortes de diagrammes ?

Sylvie : Le README en compte quarante-six types. Trente-sept sont rendus par Kroki, un service de diagrammes, et neuf viennent de quatre extensions fournies, dont des diagrammes d’architecture, de flux et des schémas infonuagiques avec de vrais logos.

Thierry : Et l’assistant, il peut appeler quoi au juste ?

Sylvie : Cinq outils. Un qui rend un diagramme, un qui le renvoie comme image en ligne, un qui vérifie la source avant, avec des erreurs qui disent comment corriger, un qui liste les types disponibles, et un qui rend plusieurs diagrammes en un seul appel.

Thierry : Que se passe-t-il en coulisses quand je demande un diagramme ?

Sylvie : Le serveur vérifie le type et les arguments, puis regarde dans un cache pour qu’une demande répétée revienne vite. Sinon, il fait le rendu. Les types Kroki passent par le service, ceux des extensions sont rendus sur place. Et si Kroki échoue, les sources PlantUML et Mermaid peuvent être retentées ailleurs.

Thierry : Je peux l’installer moi-même ?

Sylvie : Oui, une console web avec journaux en direct, métriques et limites de débit.

Thierry : Donc on retient qu’on décrit le diagramme et qu’il apparaît dans la conversation.

Sylvie : Exactement. L’article complet a la vidéo de démonstration et la chaîne de traitement étape par étape.

1. Démonstration

L’enregistrement vient du dépôt (docs/assets/mcp-app-demo.mp4). Un seul appel generate_uml_batch renvoie quatre diagrammes sous forme d’onglets dans la visionneuse MCP App ; l’utilisateur change d’onglet, puis refait le rendu d’un diagramme dans un autre format.

Les clients sans MCP Apps reçoivent le même résultat sous forme d’image en ligne et de liens, ce qu’affichent la plupart des clients de conversation :

2. Cas d’utilisation

Serveur MCP qui permet aux assistants IA de transformer une source ou une description en diagramme rendu dans la conversation.

Rendre un diagramme
Client MCP (chat IA)Kroki / PlantUML

generate_uml reçoit un diagram_type, le code source, un format et un thème optionnel, fait le rendu via Kroki (KROKI_SERVER, https://kroki.io par défaut) et renvoie le fichier, son URL et un lien vers le terrain de jeu.

Valider une source
Client MCP (chat IA)

validate_uml vérifie le type, le format et la structure de base en local, sans rendu, pour que l'assistant corrige la source avant de lancer le rendu.

Rendre un lot de diagrammes
Client MCP (chat IA)Kroki / PlantUML

generate_uml_batch rend plusieurs éléments en parallèle limité, dans l'ordre reçu, jusqu'à la limite batch_max_items.

Retoucher dans le visualiseur
DéveloppeurClient MCP (chat IA)

Dans les clients compatibles MCP Apps, le résultat s'ouvre dans ui://uml-mcp/diagram-viewer : zoom, édition de la source, changement de thème ou de format, export SVG, PNG, HTML ou PDF.

Héberger le serveur soi-même
DéveloppeurKroki / PlantUML

uv tool install uml-mcp && uml-mcp setup l'installe en local ; docker-compose.yml lance le serveur sur le port 8000 avec des conteneurs Kroki et un profil PlantUML de secours optionnel, et deploy/helm/uml-mcp vise Kubernetes.

2.1. Scénario : Dessiner une séquence de connexion depuis Cursor

  1. Ajouter le point d'accès hébergé https://uml-mcp.vercel.app/mcp à la configuration MCP, comme dans .cursor/mcp.json.
  2. Demander à l'assistant : « Dessine un diagramme de séquence d'un utilisateur qui se connecte via une passerelle d'API. »
  3. L'assistant appelle list_diagram_types, écrit la source Mermaid ou PlantUML et la vérifie avec validate_uml.
  4. Il appelle generate_uml_image ; le serveur fait le rendu via Kroki et renvoie un PNG en ligne avec les liens de rendu et de terrain de jeu.
  5. Ouvrir le lien du terrain de jeu ou le visualiseur MCP App pour retoucher la source et exporter en SVG.

3. Aperçu

Le serveur expose cinq outils, ainsi que des ressources (uml://types, uml://examples, uml://templates), des invites et des fichiers de compétences qui enseignent chaque notation à l’assistant.

OutilRôle
generate_umlRend un diagramme ; renvoie url, playground, display_markdown et les octets en base64 quand ils sont récupérés
generate_uml_imageLa même chose, renvoyée comme ImageContent MCP pour l’affichage en ligne (PNG par défaut)
validate_umlVérifie la source avant le rendu, avec des erreurs qui disent comment corriger
list_diagram_typesLe catalogue en direct des types et de leurs formats de sortie
generate_uml_batchPlusieurs diagrammes en un appel (MCP_BATCH_MAX_ITEMS, 20 par défaut)

Le README compte 46 types de diagrammes : 37 rendus par Kroki et 9 par quatre extensions fournies (graphes de forces D3 et diagrammes infonuagiques avec de vrais logos, diagrammes de pile, architecture, flux et séquences façon archify, et cartes de couches de LLM en 2D/3D).

4. Ce qui se passe lors d’un appel

generate_uml, dans mcp_core/tools/diagram_tools.py, n’est qu’une enveloppe ; le travail se fait dans generate_from_request (mcp_core/core/diagram_service.py) et run_diagram_pipeline (mcp_core/core/diagram_rendering.py).

sequenceDiagram
  participant AI as Assistant (client MCP)
  participant Tool as generate_uml
  participant Svc as generate_from_request
  participant Cache as Cache de rendu
  participant Pipe as run_diagram_pipeline
  participant K as Kroki
  participant FB as Serveur PlantUML / mermaid.ink
  AI->>Tool: diagram_type, code, output_format, theme, scale
  Tool->>Tool: resolve_diagram_type (clé exacte, sinon suggestions ou sélecteur)
  Tool->>Svc: DiagramRequest
  Svc->>Svc: validation GenerateUMLInput, type au catalogue ?
  Svc->>Cache: clé SHA-256 du type, de la source, du format, du thème, de l’échelle et du moteur
  alt présent en cache
    Cache-->>AI: résultat enregistré, cache_hit = true
  else absent
    Svc->>Pipe: rendu
    alt type d’extension
      Pipe->>Pipe: render_with_plugin
    else type Kroki
      Pipe->>K: GET /{type}/{format}/{source deflate+base64url}
      K-->>Pipe: SVG ou PNG
      opt échec de Kroki et repli activé
        Pipe->>FB: même source
      end
    end
    Pipe-->>Svc: résultat + attempts + render_ms
    Svc->>Svc: aplatit les étiquettes SVG, matricialise si PNG demandé pour un type SVG seulement, construit display_markdown
    Svc->>Cache: enregistre
    Svc-->>AI: url, playground, image, display_markdown
  end

Étape par étape :

  1. Type. mrtr.resolve_diagram_type met la clé en minuscules et l’accepte si elle est au catalogue. Sinon, si le client sait afficher un formulaire, le serveur demande à l’utilisateur de choisir parmi jusqu’à huit types proches (difflib, seuil 0,45) ; sinon, il renvoie une erreur avec ces suggestions. Le thème suit le même traitement.
  2. Validation. GenerateUMLInput (Pydantic) vérifie les arguments ; la source est limitée par MCP_MAX_CODE_LENGTH, 500 000 caractères par défaut. Un type inconnu renvoie UNSUPPORTED_DIAGRAM_TYPE avec un renvoi vers uml://types.
  3. Format. Si le client demande du PNG ou du JPEG pour un type qui ne rend que du SVG, le service rend le SVG puis le matricialise.
  4. Cache. Les appels qui n’écrivent pas de fichier sont mis en cache en mémoire. La clé est le SHA-256 d’un objet JSON contenant le type, la source sans espaces de bord, le format, le thème, l’échelle et l’identité du moteur. Valeurs par défaut : 300 secondes, 128 entrées, 32 Mio (MCP_RENDER_CACHE_*).
  5. Rendu. Les types d’extension (moteur plugin:) sont rendus localement. Tout le reste part chez Kroki : la source est compressée avec zlib au niveau 9, encodée en base64url et placée dans l’URL {kroki}/{type}/{format}/{encodé}, qui est aussi le lien rendu à l’utilisateur.
  6. Repli. Si Kroki échoue, les sources de la famille PlantUML sont renvoyées au serveur PlantUML et le Mermaid à mermaid.ink. Mermaid a un délai court de 8 secondes chez Kroki, et un disjoncteur évite le moteur Mermaid de Kroki pendant 60 secondes après des échecs répétés. Le repli est désactivé par défaut sur Vercel et avec un Kroki local, où les services publics ne seraient pas la bonne cible.
  7. Réponse. Les étiquettes HTML des SVG (foreignObject) sont converties en texte SVG simple pour que le fichier s’affiche partout, display_markdown est construit pour la conversation, et chaque résultat porte attempts, fallback_used et render_ms : un échec dit quel moteur a échoué et pourquoi.

5. Exploitation

uml-mcp admin ouvre une console web sur http://127.0.0.1:8765/admin (sur un serveur déployé, /admin) : installation, réglages, activité, journaux en direct, métriques, limites de débit, outils et extensions, clients et contrôles de qualité. En local, les modifications exigent un jeton d’installation à usage unique ; avec l’authentification d’entreprise (Entra ID), la console reste en lecture seule tant que l’écriture n’est pas activée dans les réglages.

6. Démarrage

Utilisez le serveur hébergé dans n’importe quel client MCP :

"uml-mcp": {
  "transport": "http",
  "url": "https://uml-mcp.vercel.app/mcp"
}

Ou installez-le en local et laissez la commande d’installation écrire la configuration du client :

uv tool install uml-mcp && uml-mcp setup

Demandez ensuite un diagramme à l’assistant, par exemple « Dessine un diagramme de séquence d’un utilisateur qui se connecte par une passerelle d’API. » Le dépôt fournit des configurations prêtes pour Cursor (.cursor/mcp.json), VS Code (.vscode/mcp.json), Codex, Claude Desktop et Open WebUI, et docs/installation.md couvre Docker, Helm et l’exécution depuis les sources.

7. Guide du dépôt

  • server.py, app.py : points d’entrée stdio et HTTP ; server.py résout l’objet MCP à la demande, si bien qu’un import n’écrit rien sur stdout, qui transporte le protocole stdio.
  • mcp_core/tools/ : les fonctions des outils, leurs schémas, l’aide à l’élicitation (mrtr.py), les notifications de progression des lots et l’export.
  • mcp_core/core/ : catalogue, validation, chaîne de rendu, cache de rendu, matricialisation SVG, thèmes et configuration.
  • mcp_core/plugins/, examples/plugins/ : le chargeur d’extensions et les quatre extensions fournies (D3, diagramme de pile, archify, visualiseur de LLM).
  • mcp_core/apps/ : la visionneuse MCP App (ui://uml-mcp/diagram-viewer) et le nettoyage des SVG.
  • mcp_core/admin/, mcp_core/auth/, mcp_core/observability/ : console d’administration, authentification unique et métriques.
  • tools/kroki/ : le client Kroki, l’encodage des URL, les liens d’éditeur et les aides propres à chaque langage.
  • deploy/helm/, Dockerfile, docker-compose*.yml, vercel.json : déploiement.
  • tests/ : 127 entrées, tests unitaires et d’intégration avec des bancs MCP et HTTP.

8. Limites

  • Les types rendus par Kroki dépendent d’une instance Kroki joignable, et comme la source voyage dans l’URL, les très gros diagrammes donnent des liens très longs.
  • Le cache de rendu est propre à chaque processus et en mémoire : il n’est pas partagé entre instances sans serveur.
  • Quand ils sont activés, les replis envoient la source du diagramme à des services tiers (serveur PlantUML, mermaid.ink) ; réglez MCP_DIAGRAM_FALLBACK=false si la source est privée.
  • La prise en charge des MCP Apps varie selon les clients ; les autres ne reçoivent que l’image et les liens.

13. Glossaire

Dépôt

Les fichiers source, la configuration et l’historique versionné d’un projet.

README

Le document d’entrée du dépôt, qui présente généralement son rôle et son installation.

Dépendance

Une bibliothèque, un outil ou un service nécessaire à la compilation ou à l’exécution d’un composant.

API

Une interface par laquelle des composants logiciels échangent des requêtes et des résultats. Une API n’utilise pas nécessairement HTTP.

HTTP

Un protocole de requête et réponse utilisé par les navigateurs et services web. Une requête comprend une méthode, un chemin, des en-têtes et parfois un corps.

Session

Un état conservé entre plusieurs requêtes, souvent pour suivre un utilisateur connecté. L’authentification et les permissions restent des vérifications distinctes.

Conteneur

Un environnement de processus isolé créé à partir d’une image. Les données persistantes nécessitent un stockage hors de son système de fichiers temporaire.

Docker Compose

Un format de configuration et un outil pour lancer des conteneurs, réseaux et volumes associés. L’ordre de démarrage ne garantit pas qu’un service est prêt.

Port publié

Un port de l’hôte associé au port d’un service dans un conteneur. Sa publication peut rendre le service accessible hors du réseau des conteneurs.

Interface en ligne de commande

Une interface textuelle où les commandes et arguments choisissent les opérations. Les codes de retour permettent aux scripts de détecter un succès ou un échec.

Intégration continue

Des vérifications automatiques lors des changements de source, comme la compilation, les tests et l’analyse statique. Elles ne couvrent que ce qu’elles vérifient.

MCP

Model Context Protocol : un protocole permettant à un client IA de découvrir et appeler des outils, et de lire les ressources d’un serveur.

Mermaid

Un langage de diagrammes textuel. Les nœuds et liens décrivent un modèle ; le diagramme n’exécute pas le projet.

GPU

Un processeur conçu pour les calculs parallèles, dont le rendu graphique et de nombreuses opérations numériques.

Maillage

Une surface représentée par des sommets et des éléments reliés, souvent des triangles. Sa géométrie est distincte de son matériau ou de sa texture.

Backend

Une implémentation derrière une interface commune. Selon le contexte, il peut s’agir d’un service côté serveur ou d’une implémentation graphique, d’entrée ou de stockage.
