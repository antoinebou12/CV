AINewsTracker

AINewsTracker collects financial news, analyses article text and exposes the resulting data through FastAPI. A separate strategy path uses stored information for historical backtests.

Ava: A financial headline lands, and a few seconds later somebody wants to know what it means for a stock. AINewsTracker is a Python service built around that moment, from collecting the news to testing strategies against it.

Andrew: So it's a news reader that thinks a little?

Ava: Sort of. It's a web application from AlgoÉTS, built with FastAPI. It collects financial news, analyses the text of each article and exposes what it finds through an API.

Andrew: Where does the news come from?

Ava: From RSS feeds, from GNews and from other feeds you configure. There's also a seeding step that loads company data and news from outside sources, so the service has material to work with.

Andrew: And what does analysing the text actually give you?

Ava: Sentiment, topics, and an allocation of tickers, so you know which companies an article is about. Articles end up in MongoDB, and Redis handles caching.

Andrew: How is it organised inside?

Ava: Quite cleanly. One main file assembles the service and registers the route groups: news, articles, companies, users, seeding and strategies. News goes through a processing service, then text metrics, then a repository layer before it reaches the database.

Andrew: You said strategies. Where do those fit?

Ava: That's the second half of the story. A separate path takes the stored information and runs historical backtests. You can ask for a strategy to run for a single company, or for a whole list of them.

Andrew: So the news side and the trading side share the same data.

Ava: Exactly. You can create and read articles, look a company up by its ticker, even read an article's score. And it runs either through Poetry or with Docker Compose, with FastAPI generating a documentation page for every route.

Andrew: Is there more to see in the written version?

Ava: Yes. The full page has the architecture diagram, and a companion article follows one piece of news from an incoming feed all the way to a stored article. Worth a read if you like seeing the plumbing.

1. Overview

app/main.py assembles the service, registers the route groups and configures Redis caching. News processing moves through a service, text metrics and the article repository before reaching MongoDB.

The companion article, Following financial news through AINewsTracker, follows that path from an incoming feed to a stored article.

2. Use cases

FastAPI service from AlgoÉTS that collects financial news, scores it with FinBERT and stores it in MongoDB.

Fetch news from a source
Quant analystNews feeds and APIs

The /news routes pull the Financial Modeling Prep 8-K RSS feed, GNews or a named feed with feedparser, download each article's text and save it; limits above 10 run as background tasks.

Score article sentiment
Quant analyst

TextMetrics loads ProsusAI/finbert for sentiment, Jean-Baptiste/roberta-ticker for ticker extraction and distilbart-cnn-12-6 for summaries; GET /articles/{article_id}/score returns the stored score.

Query news by company
Quant analyst

/company stores tickers, and /articles/articles_by_company_id/{company_id} or POST /articles/articles_by_company_ids return the articles linked to one or more companies.

Seed companies and news
Quant analystNews feeds and APIs

POST /seed/seed_companies and /seed/seed_news start CompanySeeder and NewsSeeder in the background; NewsSeeder reads Financial Modeling Prep stock news with FMP_API_KEY and saves the articles to MongoDB.

Serve scored articles
Backtesting service

GET /v1/articles, protected by a Bearer service token (AINEWSTRACKER_SERVICE_TOKEN), returns articles filtered by symbols and time window with sentiment label, probabilities and model name, paged by cursor.

2.1. Scenario: Collect and query Apple news locally

  1. Copy .env.example to .env, set FMP_API_KEY, then run docker-compose up --build to start the API with MongoDB and Redis.
  2. Open http://localhost:8000/api/v1/docs and call POST /seed/seed_companies.
  3. Call POST /seed/seed_news; NewsSeeder reads Financial Modeling Prep stock news in the background and stores the scored articles.
  4. Read the stored articles with GET /articles/ and check one with GET /articles/{article_id}/score.
  5. From a backtesting service, call GET /v1/articles?symbols=AAPL with the Bearer service token.

3. Getting started

cp .env.example .env
pip install poetry
poetry shell
poetry install
poetry run pytest
poetry run uvicorn app.main:app --reload

FastAPI documentation is available at http://localhost:8000/api/v1/docs according to the project guide. Docker users can start the documented stack with:

docker-compose up --build

4. Repository guide

  • app/main.py creates the application, registers routers and configures caching.
  • app/routers/ defines news, article, company, user, seed and strategy endpoints.
  • app/core/services/ contains news processing and text metrics.
  • app/core/repo/ contains persistence operations grouped by domain.
  • app/models/ defines records accepted and returned by the service.
  • app/seed/ loads company and news data from external sources.
  • app/core/trading/strategy.py handles strategy requests.

5. Features

  • ingest news through RSS, GNews and configured feeds;
  • analyse sentiment, topics and ticker allocation;
  • manage article, company, news and user records;
  • seed company and news data;
  • execute strategy requests for one or more companies;
  • run through Poetry or Docker Compose.

10. Limits

  • Sentiment and topic labels are analytical inputs, not financial advice or proof of causation.
  • Historical backtests do not guarantee future performance.
  • External feeds and market APIs have their own credentials, availability and usage terms.
  • Endpoint details can change; current source and OpenAPI take precedence.

15. Glossary

Repository

The versioned source files, configuration, and history of a project.

README

The repository’s entry document, usually covering its purpose and initial setup.

Dependency

A library, tool, or service that another component needs to build or run.

API

An interface through which software components exchange requests and results. An API does not have to use HTTP.

HTTP

A request-and-response protocol used by browsers and web services. A method, path, headers, and optional body describe a request.

Session

State kept across related requests, often to track a signed-in user. Authentication and permission checks remain separate concerns.

Container

An isolated process environment created from an image. Persistent data needs storage outside the container’s disposable filesystem.

Docker Compose

A configuration format and tool for starting related containers, networks, and volumes. Startup order alone does not guarantee service readiness.

Published port

A host port mapped to a service’s container port. Publishing a port can expose that service beyond its container network.

CLI

A text interface in which commands and arguments select operations. Exit codes let scripts detect success or failure.

Build

The steps that turn source files and dependencies into a runnable program or distributable artifact.

Mermaid

A text-based diagram language. Nodes and connections describe a model; the diagram itself does not execute the project.

Backend

An implementation behind a shared interface. Depending on context, it can mean a server-side service or a graphics, input, or storage implementation.

Database

A system for storing and querying structured records. Its schema, access rules, and persistence determine how the application can use that data.
