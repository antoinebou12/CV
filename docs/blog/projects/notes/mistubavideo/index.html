Transcript

Ava: A simulation gives you numbers. How do you turn them into a film you can show at a talk?

Andrew: That's MistubaVideo, a set of tools from the ETSim project built on Mitsuba 3, a path tracer.

Ava: What goes in?

Andrew: Sequences of 3D models, or recorded body poses and surface wear fields from a simulation. The tools render each frame and encode an MP4 or GIF with FFmpeg.

Ava: Why render after the fact?

Andrew: Because you can change the camera or the lighting without running the simulation again. You can pick front, top or perspective views, denoise on the GPU, and make heatmaps with a surface atlas panel.

Ava: Is there a standard input?

Andrew: Yes. Any project can write a versioned manifest file, and the tool validates it. There's even a demo command that makes a synthetic example. The written page has the walkthrough.

MistubaVideo

MistubaVideo renders simulation exports with Mitsuba 3, under ETSim. The batch command processes OBJ sequences; the mitsuba-video helper reads recorded body poses and surface fields through manifest and TextureFriction source adapters. Facts below come from the repository documentation as read for the project introduction.

  • Updated 2026-10-24
View sourceREADMEMarkdown

1. Overview

Why it exists. A simulation computes motion and surface change; rendering a recording shows where bodies moved and how material appearance evolved, and lets you change camera or lighting without repeating the simulation.

Best fit. Turning recorded poses and wear fields into frames, heatmaps, atlas panels and video for reports and talks.

2. Use cases

Mitsuba 3 tools from ETSim that path-trace OBJ sequences and wear-field recordings into frames, MP4 videos and GIFs.

Render an OBJ sequence
Simulation researcherMitsuba 3 and FFmpeg

python main.py multi --folder exports --regex "\d+\.obj" builds a scene XML per matching OBJ, renders it on CPU or CUDA at the chosen spp and resolution, then encodes MP4 and GIF with FFmpeg.

Render several camera views
Simulation researcher

--view front --view top or --all-views renders each frame from the front, back, left, right, top, bottom or perspective camera defined in src/mitsuba/camera.py, with the view name in the file name.

Denoise and split AOVs
Simulation researcherMitsuba 3 and FFmpeg

python main.py denoise <path> runs the OptiX denoiser from src/mitsuba/denoising.py on rendered images, and python main.py aov <file.exr> extracts the AOV layers of an EXR into separate files.

Make a field video
Simulation researcherMitsuba 3 and FFmpeg

mitsuba-video render <manifest.json> -q paper path-traces rigid bodies at their recorded poses with a field-driven material blend and heatmap, adds a UV atlas panel and a covered-area chart, and encodes an MP4.

Render a wear recording
Simulation researcherTextureFriction runs

python main.py wear render simulation_<ts> or tf-render reads a TextureFriction --record folder or .h5 file through the texturefriction source.

Write and check a manifest
Simulation researcher

Any project can emit a versioned manifest.json with ManifestWriter; mitsuba-video validate checks it against manifest-v1.schema.json, and mitsuba-video fixture creates a small synthetic example.

2.1. Scenario: Render the demo field video

  1. Install FFmpeg and Mitsuba 3, then run pip install -e "packages/mitsuba_video[texturefriction]" to get mitsuba-video and tf-render.
  2. Create a synthetic input with mitsuba-video fixture demo.
  3. Check the framing quickly with mitsuba-video preview demo.
  4. Run mitsuba-video render demo -q preview to path-trace the frames and encode the MP4.
  5. For real data, point python main.py wear render at a TextureFriction simulation_<ts> folder with -q paper.

3. Getting started

python main.py multi --folder exports          # batch-render an OBJ sequence
mitsuba-video inspect path/to/manifest.json    # check the input data
mitsuba-video preview path/to/manifest.json    # check camera and framing
mitsuba-video render path/to/manifest.json -q preview

Quality presets: preview, draft, paper. encode reassembles existing frames into video; FFmpeg does the encoding.

4. Features and components

StageData
InputMeshes, materials, recorded poses and surface fields; a versioned manifest (bodies, meshes, materials, poses, field images) or a TextureFriction recording through a source adapter; ManifestWriter lets another simulator export the format
ProcessingApply recorded poses, blend base and affected materials using the surface field, Mitsuba 3 path tracing; optional heatmap, UV-atlas panel and covered-area chart
OutputBeauty and composite frames, field-area CSV, render_config.json with settings and timings, MP4; optional linear EXR frames

6. Constraints and checks

  • The area chart measures the recorded field’s covered area, not the visible area of the rendered object.
  • Keep display settings with the render: changing the heatmap range makes the same field look different.
  • The package documents pytest tests for transforms, material blending, OBJ/MTL readers and the manifest schema and writer; no measured coverage percentage is quoted here.

11. Glossary

Repository

The versioned source files, configuration, and history of a project.

README

The repository’s entry document, usually covering its purpose and initial setup.

Dependency

A library, tool, or service that another component needs to build or run.

HTTP

A request-and-response protocol used by browsers and web services. A method, path, headers, and optional body describe a request.

Published port

A host port mapped to a service’s container port. Publishing a port can expose that service beyond its container network.

CLI

A text interface in which commands and arguments select operations. Exit codes let scripts detect success or failure.

Mermaid

A text-based diagram language. Nodes and connections describe a model; the diagram itself does not execute the project.

GPU

A processor designed for parallel workloads, including graphics rendering and many numerical operations.

Mesh

A surface represented by vertices and connected elements, often triangles. Its geometry is distinct from its material or texture.

Video decoder

A component that reconstructs video frames from a compressed stream. Decoding and displaying a frame are separate stages.
