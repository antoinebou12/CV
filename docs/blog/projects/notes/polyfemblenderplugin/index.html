PolyFEMBlenderPlugin

PolyFEMBlenderPlugin is an experimental Blender extension that turns selected objects, materials and contact settings into a PolyFEM JSON setup and runs the finite-element simulation without leaving Blender. It was written for the ÉTS lab’s simulation work and is published under ETSim, for people who prepare scenes in Blender but solve them with PolyFEM.

Ava: Picture a scene you've built in Blender: a soft block, a metal plate, a little contact between them. You want to know how it actually deforms. Normally that means leaving Blender and juggling files and command lines.

Andrew: Which sounds like a lot of switching between tools. Is there a shortcut?

Ava: That's exactly what PolyFEMBlenderPlugin is for. It's an experimental Blender extension that turns your selected objects, their materials and the contact settings into a setup file for PolyFEM, a finite-element solver. Then it runs the simulation without you leaving Blender.

Andrew: Why did Antoine build it?

Ava: He wrote it for the simulation work at the ÉTS lab. It's meant for people who prepare their scenes in Blender but solve them with PolyFEM. It's published under the ETSim group on GitHub.

Andrew: So what do I actually see inside Blender?

Ava: A PolyFEM panel in the Physics tab. You pick the objects, give each one elastic properties, either from presets like steel, copper or aluminium, or with your own values. Then there are collapsible sections for contact, time, boundary conditions, the solver and the output.

Andrew: And the meshes themselves? A solver needs a particular kind.

Ava: Right. The add-on exports each mesh as STL or OBJ, or it can fill it with tetrahedra using TetWild and save it as an MSH file. Then it writes the full PolyFEM setup file, and you can even export only the objects you've selected.

Andrew: Does Blender freeze while the simulation runs?

Ava: No. PolyFEM runs in a background thread, either through Docker or as a local program, so the interface stays usable. Docker is the default, which means you don't have to install the solver yourself.

Andrew: And when it's done, do you get the results back in the scene?

Ava: Yes, and that's the nice part. A Render Animation button reads each time step, converts it to a mesh, and keyframes them so the deformation plays back as an animation right in Blender.

Andrew: So the whole loop, scene, solver and playback, lives in one place.

Ava: Exactly. It needs Blender 4.2 or later, and the written page walks through the installation and the repository layout if you want to try it.

1. Overview

polyfem/__init__.py registers one panel, the property groups and the operators. On registration it also installs meshio with pip into Blender’s user modules folder.

  • polyfem/panels/polyfem_json.py draws the PolyFEM panel in the Physics tab of the Properties editor: execution mode (Docker or executable) for PolyFEM and TetWild, the selected objects with their materials and export format, then collapsible sections for export, contact, time, space, boundary conditions, materials, solver and output settings.
  • polyfem/operators/create_polyfem_json.py exports each mesh (STL, OBJ, or MSH through TetWild) and writes the PolyFEM JSON file with geometry, materials, contact, time, boundary_conditions, solver and output blocks.
  • polyfem/operators/run_polyfem.py starts PolyFEM in a background thread, either docker run antoinebou12/polyfem --json /data/<file> with the project folder mounted on /data, or a local executable. Its Render Animation operator reads the step_*.vtu results, adds the solution displacement, converts each step to OBJ with meshio and keyframes the visibility of each imported mesh.
  • polyfem/properties/polyfem.py holds the settings, including material presets (steel, copper, aluminium and others), integrators (implicit Euler, explicit Euler, implicit Newmark) and Eigen linear solvers.

2.1. Scenario: Simulate a contact scene and play it back in Blender

  1. Install the zipped polyfem folder through Edit > Preferences > Add-ons and enable PolyFem.
  2. In Properties > Physics > PolyFEM, choose Docker execution and pull antoinebou12/polyfem and yixinhu/tetwild.
  3. Select the meshes, apply a material preset and set contact, time step and end time.
  4. Click Create JSON Configuration to write the meshes and the JSON file to the export path.
  5. Click Run PolyFem Simulation, then Render Animation to import the step_*.vtu results as keyframed meshes.

3. Getting started

The README installs the add-on from a zip of the polyfem/ folder: Edit > Preferences > Add-ons > Install, then enable PolyFem. Blender 4.2 or later is required by blender_manifest.toml. The default execution mode uses Docker:

docker pull yixinhu/tetwild:latest
docker pull antoinebou12/polyfem:latest

The CI workflow builds the extension package with Blender’s own command:

blender --command extension build --source-dir polyfem --output-dir docs
blender --command extension server-generate --repo-dir=docs --html

4. Repository guide

  • polyfem/ is the extension itself (blender_manifest.toml, __init__.py, operators/, panels/, properties/).
  • polyfem/operators/create_polyfem_json.py handles mesh export, TetWild, materials, Docker image pulls and the JSON file.
  • polyfem/operators/run_polyfem.py runs PolyFEM, imports results, opens the PolyFEM documentation and clears the cache.
  • polyfem/properties/polyfem.py defines every panel field and preset.
  • .github/workflows/build.yml builds the extension zip and an extension repository index (docs/index.json), then deploys docs/ to the gh-pages branch.
  • docs/ holds built packages polyfem-1.0.10.zip and polyfem-1.0.11.zip with their index.
  • zip-plugin.py and download-wheels.py are helper scripts to zip the add-on and download wheels for meshio, trimesh and tetgen.

5. Features

  • Assign elastic material properties (E, ν, ρ) to objects from presets or custom values.
  • Export meshes to STL or OBJ, or tetrahedralize them to MSH with TetWild in Docker or as a local executable.
  • Set contact (dhat, friction coefficient, epsv), time integration, boundary-condition method and right-hand side, linear solver and ParaView output options.
  • Write a complete PolyFEM JSON file, with optional export of selected objects only.
  • Run PolyFEM through Docker or a local executable without blocking the Blender interface.
  • Import VTU time steps back as a keyframed mesh sequence.

6. Limits

  • The README calls the add-on experimental and lists crashes with complex geometry and mesh-export edge cases as known issues.
  • The panel is registered in the Properties editor’s Physics tab, while the README describes a 3D Viewport sidebar tab.
  • FBX and glTF appear in the export menu but the operator rejects them.
  • blender_manifest.toml lists only windows-x64 as a platform, and the add-on needs Docker or local PolyFEM and TetWild builds.
  • The README states GPL-3.0, while LICENSE and the manifest state MIT.
  • The README badges and file tree refer to an older repository name and to a panels/poly_fem.py file that is not in the tree.
  • There are no tests. The workflow only builds and publishes the package.

11. Glossary

Repository

The versioned source files, configuration, and history of a project.

README

The repository’s entry document, usually covering its purpose and initial setup.

Dependency

A library, tool, or service that another component needs to build or run.

HTTP

A request-and-response protocol used by browsers and web services. A method, path, headers, and optional body describe a request.

Container

An isolated process environment created from an image. Persistent data needs storage outside the container’s disposable filesystem.

Volume and bind mount

A volume is storage managed by the container platform; a bind mount exposes a chosen host path inside a container.

Published port

A host port mapped to a service’s container port. Publishing a port can expose that service beyond its container network.

CLI

A text interface in which commands and arguments select operations. Exit codes let scripts detect success or failure.

Build

The steps that turn source files and dependencies into a runnable program or distributable artifact.

Continuous integration

Automated checks that run when source changes, such as building, testing, and linting. Passing checks cover only what those checks exercise.

GPU

A processor designed for parallel workloads, including graphics rendering and many numerical operations.

Mesh

A surface represented by vertices and connected elements, often triangles. Its geometry is distinct from its material or texture.
