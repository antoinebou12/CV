antoinebou12: How the GitHub profile is assembled

This is the repository behind my GitHub profile README. It combines ordinary Markdown with images, embedded widgets and scheduled updates. There is no application server in the profile itself.

2. Use cases

GitHub profile README with links, badges, pinned projects and stats, kept current by scheduled Actions.

Read the profile and links
Profile visitor

README.md opens with the platform and graphics headline, then links (GitHub, LinkedIn, website, CV, email), certification badges and the main languages and tools.

Browse pinned projects
Profile visitor

A collapsible Featured projects section shows pin cards for repositories such as AINewsTracker, hass_renpho, ipc-toolkit and TrueMapData, plus the DashCTRL, ETSim and UFOKEK organisations.

Refresh 3D contribution chart
GitHub Actions

github-profile-3d-contrib.yml runs daily at 05:00 UTC, generates the 3D contribution calendar, keeps only profile-night-green.svg and commits it.

Update LeetCode badges
GitHub Actions

update-readme.yml runs daily at 12:00 UTC, fetches stats from leetcodestats.cyclic.app and rewrites the badges between the LEETCODE_STATS markers in README.md.

Check README links
Profile ownerGitHub Actions

On each push or pull request to main or master, check-links.yml runs lychee on README.md and docs/**/*.md and writes a job summary.

Publish the Jekyll page
Profile ownerGitHub Actions

jekyll-pages.yml builds docs/ with the jekyll-theme-primer theme and deploys it to GitHub Pages; docs/index.md points back to the profile README.

2.1. Scenario: Edit the profile and let automation keep it current

  1. The owner edits README.md, for example the Featured projects list, and pushes to master.
  2. check-links.yml runs lychee on README.md and the docs Markdown and reports broken links.
  3. jekyll-pages.yml builds docs/ and deploys the small Jekyll site to GitHub Pages.
  4. Each day, github-profile-3d-contrib.yml regenerates profile-night-green.svg and commits it.
  5. A visitor opens the profile page and sees the updated README, stats cards and 3D calendar.

5. Features and components 2

README and assets
README.md is the visible profile document. The images, models and profile-3d-contrib directories hold assets used alongside it. GitHub renders the document, while linked services may generate their own images separately.
Scheduled changes
The update-readme workflow fetches LeetCode statistics, builds badge URLs and replaces the text between dedicated README markers. Separate workflows handle the contribution graphic, link checks and Pages.

11. Glossary

Repository

The versioned source files, configuration, and history of a project.

README

The repository’s entry document, usually covering its purpose and initial setup.

Dependency

A library, tool, or service that another component needs to build or run.

HTTP

A request-and-response protocol used by browsers and web services. A method, path, headers, and optional body describe a request.

Build

The steps that turn source files and dependencies into a runnable program or distributable artifact.

Continuous integration

Automated checks that run when source changes, such as building, testing, and linting. Passing checks cover only what those checks exercise.

GPU

A processor designed for parallel workloads, including graphics rendering and many numerical operations.

Mesh

A surface represented by vertices and connected elements, often triangles. Its geometry is distinct from its material or texture.
