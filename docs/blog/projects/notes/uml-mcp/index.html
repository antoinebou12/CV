uml-mcp: From an MCP tool call to a diagram

uml-mcp exposes diagram tools to MCP clients. The client supplies diagram source and options; the server validates and routes the request to rendering services, then returns diagram results and useful editor links.

Overview

Why it exists

Flagship Model Context Protocol (MCP) server generating PlantUML, Mermaid, and Kroki directly from LLMs (Claude, Cursor, ChatGPT) with zero local dependencies.

Best fit

Interactive architectural diagram generation for AI pair programming and automated design docs.

Lockfile and requirements.txt

CONTRIBUTING.md

uv.lock is the runtime source of truth for CI, Vercel, and release validation. Deploy/install paths export from the lockfile at runtime. Keep requirements.txt updated for users that still install with pip: Run this after changing runtime dependencies in pyproject.toml / uv.lock, then commit the updated requirements.txt. Transitive pins: Some packages are pinned only in [tool.uv] override-dependencies in pyproject.toml (they are not direct Poetry deps). Dependabot is configured for the uv ecosystem so PRs target uv.lock consistently. After merging a dependency PR, re-export requirements.txt if the lockfile changed so CI’s “export matches requirements.txt” step stays green.

Health check (HTTP deployment)

docs/configuration.md

When running the FastAPI app (app.py) for HTTP deployment (e.g. Vercel, Docker, uvicorn), a health endpoint is available:

  • Endpoint: GET /health (no authentication required)
  • Response: {“status”: “healthy”, “modules_available”: true|false}
  • status: Always “healthy” when the server is up.
  • modules_available: Whether diagram backends (Kroki, PlantUML, etc.) could be loaded. Use /health for load balancers, Kubernetes or Docker liveness/readiness probes, Vercel checks, and similar monitoring whenever you run the FastAPI app (app.py). When running the MCP server via fastmcp run with HTTP transport only (no FastAPI app), the standalone server does not expose /health unless you add a custom route; use the FastAPI app if you need the health endpoint.

Features and components 2

A quiet entry point
server.py delegates startup to mcp_core.core.server. It resolves the mcp object lazily through __getattr__, avoiding server construction and stdout output merely from importing the module. That matters when stdout carries the stdio protocol.
Transport and rendering
The server supports stdio and HTTP entry paths. The core groups tool registration, configuration and Kroki integration. Rendering is a downstream operation: the MCP layer describes tools and carries their inputs and results.

MCP tool contract

The hosted service accepts MCP JSON-RPC at /mcp. tools/list returns input and output schemas. A client sends tools/call with a tool name and structured arguments.

Request example
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "tools/call",
  "params": {
    "name": "generate_uml",
    "arguments": {
      "diagram_type": "mermaid",
      "code": "flowchart LR\n  Client --> Server",
      "output_format": "svg"
    }
  }
}

Response and errors

Read result.structuredContent: success, url, playground and output_format describe the render. On failure, inspect error and error_detail; MCP protocol errors and tool-level isError must be handled separately. A URL response does not mean that image bytes are embedded in the reply.
Use validate_uml for syntax checks without a render. generate_uml_batch renders several items with per-item results. Send only public diagram text to the hosted service; renderer URLs can encode that text.
Authentication, limits and pagination

This public endpoint answered the documentation build without an Authorization header. That observation does not define authentication for every deployment. No fixed quota was advertised by tools/list. Rendering is a single-result operation; catalog discovery should follow MCP pagination if the server returns a cursor.

Glossary

Repository

The versioned source files, configuration, and history of a project.

README

The repository’s entry document, usually covering its purpose and initial setup.

Dependency

A library, tool, or service that another component needs to build or run.

HTTP

A request-and-response protocol used by browsers and web services. A method, path, headers, and optional body describe a request.

Container

An isolated process environment created from an image. Persistent data needs storage outside the container’s disposable filesystem.

Published port

A host port mapped to a service’s container port. Publishing a port can expose that service beyond its container network.

CLI

A text interface in which commands and arguments select operations. Exit codes let scripts detect success or failure.

Build

The steps that turn source files and dependencies into a runnable program or distributable artifact.

MCP

Model Context Protocol: a protocol through which an AI client discovers and calls tools and reads resources from a server.

Mermaid

A text-based diagram language. Nodes and connections describe a model; the diagram itself does not execute the project.

GPU

A processor designed for parallel workloads, including graphics rendering and many numerical operations.
