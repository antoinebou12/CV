SpringBootFilesUploader

SpringBootFilesUploader is a Kotlin REST API built on Spring Boot 2.6.3. The name describes its first job: accept a file upload, put the bytes in an S3-compatible bucket and the description in MongoDB, and serve the file back by id. The code goes further than the name. The same application also lists and controls Docker containers, pings a Caddy server and runs commands over SSH, all behind JWT authentication with three roles. The last commit dates from February 2022, and the README is a single line, so everything below comes from the source.

Ava: Some projects are named for their first job and then quietly grow. SpringBootFilesUploader started as a way to upload files, and ended up as a small control console for a server.

Andrew: Let's start at the beginning. What does the upload part do?

Ava: It's a Kotlin API built on Spring Boot. You send it a file, it puts the bytes in an S3-compatible bucket, which can be MinIO, and it stores the file's description in MongoDB. Later you ask for the file by its id and it hands it back.

Andrew: Why split it in two places?

Ava: Each store does what it's good at. The bucket holds the heavy content under a unique folder name, and the database keeps the light information: name, extension, content type and size. That makes lookups fast and keeps downloads simple.

Andrew: And who's allowed to upload?

Ava: Everything sits behind JWT authentication with three roles. Moderators and admins can upload, any signed-in user can download, and only an admin can create another admin account. The upload also checks the file extension against a list that covers spreadsheets, Word documents, PDFs, common images, video, audio and archives.

Andrew: You said it grew beyond uploads. How?

Ava: The same application also drives Docker. Through the Docker Engine, it can list containers, create them, start, stop, restart and rename them. Moderators and admins can handle most of that, while creating and renaming is reserved for admins.

Andrew: So a web request can start a container?

Ava: Yes. It also pings a Caddy server through its admin interface, and it can run commands on remote machines over SSH, which is restricted to admins. All of it is described in an OpenAPI page generated automatically, so you can explore the endpoints.

Andrew: It sounds like a Swiss army knife for a home server.

Ava: That's a fair picture. The code is organized in clean layers, with controllers, services and repositories, and the page lists the six controllers and what each one is allowed to do.

Andrew: Where do I find the details?

Ava: In the written page. It has a diagram of the whole upload and download flow, the project structure and the external services it expects, with the default addresses.

1. Overview

Six controllers make up the API. Paths are relative to the server root; /auth/** and the API docs are public, everything else needs a bearer token (SecurityConf.kt).

AuthController (/auth)POST /signin, POST /signup, POST /signup/adminpublic; /signup/admin needs ADMIN
FilesController (/files)POST /documents (multipart field document), GET /{id}upload: MODERATOR or ADMIN; download: any role
UserController (/user)GET /{id}/page, GET /profile, GET /mod, GET /adminper endpoint
DockerController (/containers)GET /ping, GET /list, PUT /create, POST /start/{name}, /stop/{name}, /restart/{name}, /rename/{name}/{newName}MOD or ADMIN; create and rename ADMIN
CaddyController (/caddy)GET /pingauthenticated

The OpenAPI page is served by springdoc at /api-docs (application.yml).

2. Use cases

Kotlin Spring Boot API that stores uploaded files in MinIO/S3 behind JWT roles, with Docker and SSH admin endpoints.

Sign up and get a JWT
API userMinIO S3 and MongoDB

POST /auth/signup saves a user with hashed password and roles in MongoDB; POST /auth/signin returns a JwtResponse with the token and roles (AuthController.kt, JwtUtils.kt).

Upload a document
Moderator or adminMinIO S3 and MongoDB

POST /files/documents (moderator or admin) checks the extension against DOC_FILE_EXTENSION_REGEX, writes the bytes to the S3 bucket under files/<uuid>/<name> and records metadata in MongoDB.

Download a stored file
API userMinIO S3 and MongoDB

GET /files/{id} looks up the file record in MongoDB, reads the object from S3 and returns it as an attachment with its content type and size.

Manage Docker containers
Moderator or admin

The /containers routes list, create, start, stop, restart and rename containers through docker-java against the Docker host set in application.yml (tcp://127.0.0.1:2375).

Run a remote SSH command
Moderator or admin

POST /ssh/cli (admin only) opens an Apache SSHD session with the host, port and credentials in the request body and returns the command output.

2.1. Scenario: Store a PDF and fetch it back

  1. Start MongoDB on localhost:27017 and MinIO on localhost:9000, as configured in application.yml, then run ./gradlew bootRun.
  2. POST /auth/signup with a username, email, password and the role "mod".
  3. POST /auth/signin and copy the JWT from the response.
  4. POST /files/documents with the PDF in the multipart field "document" and the Bearer token; the response returns fileId and fileName.
  5. GET /files/{fileId} to download the PDF, or browse the routes in Swagger UI at /api-docs.

3. How an upload works

sequenceDiagram
  participant C as Client
  participant F as JWT filter
  participant FC as FilesController
  participant FS as FilesService
  participant S3 as FileS3 (S3 / MinIO)
  participant M as FilesMongo (MongoDB)
  C->>F: POST /files/documents, Bearer token, multipart "document"
  F->>FC: authenticated user with roles
  FC->>FC: @PreAuthorize MODERATOR or ADMIN, extension regex check
  FC->>FS: addDocument(bytes, name, ext, contentType, size)
  FS->>S3: putObject(bucket "fus", "files/{uuid}/{name}")
  FS->>M: getNewFileId() = count + 1, save FileModel
  FS-->>C: 200 {fileId, fileName}
  C->>FC: GET /files/{fileId}
  FC->>M: getFile(id) → path, name, type, size
  FC->>S3: getObject(path)
  FC-->>C: bytes with Content-Disposition attachment
  1. AuthTokenFilter reads the bearer token, JwtUtils validates it with the jwtSecret from the configuration, and the user’s roles come from MongoDB.
  2. FilesController.addDocument rejects a missing part and checks the filename against DOC_FILE_EXTENSION_REGEX: spreadsheets, Word documents, PDF, common images, MP4, MOV, ZIP, MP3, WAV, ISO and RAR. Only the extension is checked, not the content. The size check is commented out.
  3. FilesService.addDocument builds the object key files/{random UUID}/{original name} and writes the bytes through the FileRepository interface, implemented by FileS3 with the AWS SDK. FileS3 creates the bucket at startup if it does not exist.
  4. The service then asks FilesMongo for an id, which is the number of documents in the collection plus one, and saves a FileModel (id, path, name, extension, UUID, content type, size).
  5. A download looks the id up in MongoDB, reads the object from its stored path and returns it with the saved content type and length.

The bytes are written before the metadata. If the MongoDB save fails, the object stays in the bucket with nothing pointing to it.

7. Getting started

Start MongoDB and MinIO locally (the repository’s docker-compose.yml is empty), then run the app with the local profile, which application.yml activates by default:

docker run -d -p 27017:27017 mongo
docker run -d -p 9000:9000 -e MINIO_ROOT_USER=minioadmin -e MINIO_ROOT_PASSWORD=minioadmin minio/minio server /data
./gradlew bootRun

The local profile also points to a Spring Cloud Config server on port 8888. Roles are read from MongoDB’s role collection and nothing in the code creates them, so insert ROLE_USER, ROLE_MODERATOR and ROLE_ADMIN before signing up.

8. Limits

  • Self-service moderator role. POST /auth/signup maps a requested role "mod" to ROLE_MODERATOR, so anyone can create an account allowed to upload files.
  • Role names that never match. DockerController checks hasRole('MOD'), but the roles are ROLE_USER, ROLE_MODERATOR and ROLE_ADMIN; only admins pass those checks.
  • Sequential, racy file ids. getNewFileId() returns the document count plus one: two concurrent uploads can get the same id, and a deletion makes the next id collide.
  • Unbounded uploads in memory. Multipart limits are set to 500,000 MB, the size check is commented out, and document.bytes loads the whole file into memory before it is sent to S3.
  • Remote command execution by design. /ssh/cli opens a shell on any host and runs the given command for an admin, and /containers talks to an unauthenticated Docker TCP socket.
  • Committed defaults. jwtSecret: secret, MinIO minioadmin keys, a config-server password and a personal email are in the YAML files.
  • Build and docs. The Dockerfile copies project-0.0.2.jar while the build produces version 0.0.3, the Compose file and README are empty, and the only test checks that the context loads.

13. Glossary

Repository

The versioned source files, configuration, and history of a project.

README

The repository’s entry document, usually covering its purpose and initial setup.

Dependency

A library, tool, or service that another component needs to build or run.

API

An interface through which software components exchange requests and results. An API does not have to use HTTP.

HTTP

A request-and-response protocol used by browsers and web services. A method, path, headers, and optional body describe a request.

Session

State kept across related requests, often to track a signed-in user. Authentication and permission checks remain separate concerns.

Container

An isolated process environment created from an image. Persistent data needs storage outside the container’s disposable filesystem.

Docker Compose

A configuration format and tool for starting related containers, networks, and volumes. Startup order alone does not guarantee service readiness.

Volume and bind mount

A volume is storage managed by the container platform; a bind mount exposes a chosen host path inside a container.

Published port

A host port mapped to a service’s container port. Publishing a port can expose that service beyond its container network.

CLI

A text interface in which commands and arguments select operations. Exit codes let scripts detect success or failure.

Build

The steps that turn source files and dependencies into a runnable program or distributable artifact.

Mermaid

A text-based diagram language. Nodes and connections describe a model; the diagram itself does not execute the project.

Backend

An implementation behind a shared interface. Depending on context, it can mean a server-side service or a graphics, input, or storage implementation.

Database

A system for storing and querying structured records. Its schema, access rules, and persistence determine how the application can use that data.

Firmware

Software running on a device or microcontroller to control its hardware and communication.
