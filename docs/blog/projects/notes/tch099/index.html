TCH099: One PHP router for pages and API calls

TCH099 is a teaching-oriented web project that combines static frontend pages with PHP API handlers. The route file makes the boundary visible: some paths return HTML files, while others dispatch to server-side scripts.

Features and components 2

Page routes
routes.php includes router.php, maps the home and login paths to frontend files, and defines 403 and 404 pages. The /admin callback explicitly branches on isAdmin before choosing its response.
API handlers
Login, signup, logout and user_details use individual API scripts. Demonstration routes include a language parameter and random-image responses. Their handlers own request processing; the router only chooses where it goes.

HTTP API and permissions

routes.php maps the paths below. The README shows paths such as /api/login.php and French status text. The handlers use the paths in this table and English messages. The access column records a check found in the handler.

Access checks read from the handlers. A README label of admin appears here only when the code checks it.

POST/api/loginNo session check. loginUser verifies the password hash.api/login.php

Response and errors

  • Success: api/login.php returns status: success, message: Login successful, and redirect: /home.
  • Failed credentials: the JSON body contains status: error and Invalid username or password.
  • Other HTTP methods: the JSON body contains Invalid request method.
  • Message language: the handler uses English, while the README examples use French.
  • Session details: GET /api/user_details requires user_loggedin and returns user_details from the session.
  • Client list: GET /api/clients also requires the admin role. Its SELECT * FROM Clients query includes the password column in a successful response.
  • Public demos: GET and POST requests to /api/hello-world/$langue and /api/random-image have no session check. Hello World uses the session username for prenom when available.
  • Random image: imageType: human returns the thispersondoesnotexist.com URL. Every other value calls The Cat API.
Authentication, limits and pagination

POST /api/signup accepts role admin or client from the JSON body. Nothing in signup.php requires an existing admin session before that role is stored. router.php sends Access-Control-Allow-Origin: *. These handlers do not set a rate limit. GET /admin is a page: routes.php calls isAdmin() and otherwise includes 403.html. Login does not set an HTTP error status; failures stay in the JSON body.

Glossary

Repository

The versioned source files, configuration, and history of a project.

README

The repository’s entry document, usually covering its purpose and initial setup.

Dependency

A library, tool, or service that another component needs to build or run.

API

An interface through which software components exchange requests and results. An API does not have to use HTTP.

HTTP

A request-and-response protocol used by browsers and web services. A method, path, headers, and optional body describe a request.

Session

State kept across related requests, often to track a signed-in user. Authentication and permission checks remain separate concerns.

Container

An isolated process environment created from an image. Persistent data needs storage outside the container’s disposable filesystem.

Published port

A host port mapped to a service’s container port. Publishing a port can expose that service beyond its container network.

CLI

A text interface in which commands and arguments select operations. Exit codes let scripts detect success or failure.

Build

The steps that turn source files and dependencies into a runnable program or distributable artifact.

Webhook

An HTTP request sent to another system when an event occurs. The receiver needs to validate the request before acting on it.
