Maestro: Sheet music through an external conversion pipeline

This Maestro fork connects a React upload interface to a Spring backend and external music-conversion tools. Turning a score image into MIDI passes through an optical-recognition stage and an intermediate score representation.

1. Overview

1.1. Why it exists

Optical Music Recognition (OMR) pipeline translating sheet music scans into MIDI score sequences.

1.2. Best fit

Digitization of physical sheet music for playback and editing.

2. Use cases

Web app that turns a scanned music sheet (PDF, PNG, JPG) into a MIDI file, with optional tempo overrides.

Upload a music sheet
Musician

The React form in maestro-app/src/pages/MusicSheetUploadForm/MusicSheetUploadForm.tsx takes a dropped file and a MIDI file name, then useMaestroClient.ts checks GET /health before posting to /convert.

Set tempos per measure
Musician

The form keeps a list of tempo, measure and force entries (default 120 at measure 1) and sends it as the JSON field tempos.

Recognize notes with Audiveris
Audiveris OMR engine

POST /convert in ConvertController.java checks the file (10 MB limit, PDF/JPG/PNG signature) and AudiverisController.java runs Audiveris in batch mode to export a .mxl file.

Convert MusicXML to MIDI
music21 (Python)

backend/src/main/MxlToMidi.py loads the .mxl with music21, applies dynamics and the requested tempo marks, and writes the .mid file.

Download the MIDI file
Musician

The backend returns the .mid as an attachment and the frontend saves it with js-file-download; input and output folders are cleaned three seconds later.

Switch English or French
Musician

LanguageSwitcher.tsx toggles i18next between en-US and fr-CA, using the strings in maestro-app/public/locales/.

2.1. Scenario: Turn a PDF score into a MIDI file locally

  1. Copy the Audiveris bin and lib folders into backend/audiveris/dist as backend/README.md explains.
  2. Start both services with docker-compose up -d (backend on port 8080, frontend on port 3000).
  3. Open localhost:3000, drop a PDF score and enter a MIDI file name.
  4. Add a tempo row, for example 90 at measure 1, and submit the form.
  5. The backend runs Audiveris, then MxlToMidi.py, and the browser downloads the .mid file.

5. Features and components 2

Upload boundary
ConvertController accepts multipart uploads at /convert. It rejects empty files, checks the 10 MiB size limit and calls a file-signature validator before saving the input. Optional tempo input travels with the conversion request.
External processes
AudiverisController builds an OS-dependent command and waits for the Audiveris process. The backend also includes MxlToMidi.py. Process startup, intermediate files and the returned download are separate failure points.

12. Glossary

Repository

The versioned source files, configuration, and history of a project.

README

The repository’s entry document, usually covering its purpose and initial setup.

Dependency

A library, tool, or service that another component needs to build or run.

HTTP

A request-and-response protocol used by browsers and web services. A method, path, headers, and optional body describe a request.

Container

An isolated process environment created from an image. Persistent data needs storage outside the container’s disposable filesystem.

Published port

A host port mapped to a service’s container port. Publishing a port can expose that service beyond its container network.

CLI

A text interface in which commands and arguments select operations. Exit codes let scripts detect success or failure.

Build

The steps that turn source files and dependencies into a runnable program or distributable artifact.

Backend

An implementation behind a shared interface. Depending on context, it can mean a server-side service or a graphics, input, or storage implementation.

Firmware

Software running on a device or microcontroller to control its hardware and communication.

Fork

A separate repository derived from another project. A change in a fork is not automatically a change in the upstream project.
