Experimenting with technical indicators using Python and backtesting

May 14, 2024 3 min read
PythonTradingBacktestingCryptoStocks

Ava: What happens if you take one simple trading rule and run it, at once, on every stock in the S and P five hundred and hundreds of crypto pairs? Antoine built a tool to find out.

Andrew: Hundreds of backtests in one go?

Ava: Exactly. Instead of judging a rule on one hand-picked chart, you see the whole spread of outcomes, from the best result to the worst, and everything in between.

Ava: It's an EMA crossover. An EMA is a moving average that weighs recent prices more. When the twenty-period one crosses above the eighty-period one, the strategy buys. When it crosses back, it sells. Each trade has a ten percent stop loss and a twenty-five percent take profit.

I batch-ran an EMA crossover strategy across the S&P 500 and a list of crypto pairs with BatchBacktesting[1], using Financial Modeling Prep for equities and Binance for crypto. This post shows what the runner does, how to read the outrageous rows at the top and bottom of the leaderboard, and why none of it is a live trading system. The original article is in French on Medium.

1. What BatchBacktesting does

  1. Pulls daily OHLCV from Financial Modeling Prep (S&P 500 list) or Binance (crypto list).
  2. Applies a strategy class to each ticker with backtesting.py[2].
  3. Writes CSV results and optional HTML charts under output/.

It is a screening hammer, not a portfolio manager.

2. Setup

pip install numpy httpx rich backtesting pandas_ta

The notebook defines the API helpers itself (make_api_request, get_SP500, get_all_crypto, price history fetchers). It only needs the two base URLs and your keys:

BASE_URL_FMP = "https://financialmodelingprep.com/api/v3"
BASE_URL_BINANCE = "https://fapi.binance.com/fapi/v1/"
FMP_API_KEY = "YOUR_FMP_API_KEY"
BINANCE_API_KEY = "YOUR_BINANCE_API_KEY"

Keep real keys in environment variables, not in the notebook you commit.

3. The EMA strategy

Buy when the 20-period EMA crosses above the 80-period EMA, sell on the opposite cross. Each entry carries a 10 % stop loss and a 25 % take profit.

class EMA(Strategy):
    n1 = 20
    n2 = 80

    def init(self):
        close = self.data.Close
        self.ema20 = self.I(taPanda.ema, close.s, self.n1)
        self.ema80 = self.I(taPanda.ema, close.s, self.n2)

    def next(self):
        price = self.data.Close
        if crossover(self.ema20, self.ema80):
            self.position.close()
            self.buy(sl=0.90 * price, tp=1.25 * price)
        elif crossover(self.ema80, self.ema20):
            self.position.close()
            self.sell(sl=1.10 * price, tp=0.75 * price)

4. Running the batch

tickers = get_SP500()
run_backtests(tickers, strategy=EMA, num_threads=12, generate_plots=True)

tickers = get_all_crypto()
run_backtests(tickers, strategy=EMA, num_threads=12, generate_plots=True)

run_backtests spreads the tickers over a thread pool and writes one chart per instrument, such as this AAPL chart[3]. The repository does not ship precomputed results: run it locally to get your own output/ folder.

The chart puts the EMA return next to buy-and-hold. OMGUSD made about 200 % with the rule while buy-and-hold lost about 80 %: the gain came from being short through a collapse, not from a reliable edge.

6. Where the full code lives

The Medium article pastes every helper: HTTP calls, threading, CSV writers and plotting. Those belong in the BatchBacktesting repository[1], where they are maintained. The follow-up post adds a MACD strategy to the same runner.

7. When not to use this

MisuseWhy it hurts
Deploying the top ticker liveOverfit to the window
Ignoring fees and slippageThe backtest inflates
Skipping out-of-sample datesA regime change breaks the rule

8. Takeaway

Batch runs teach the distribution of outcomes under a simple rule: invaluable for humility, dangerous as autopilot.
