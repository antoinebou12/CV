## Learned User Preferences

- For French cover letters, prefer a natural, direct, human register over stiff or AI-sounding prose.
- Structure cover letters with an early value or role hook, concrete proof and metrics, and optional short employer-specific tailoring; complement the CV instead of repeating it as a credential list.
- Position the profile around **platform and graphics** (header `\position` and letters: e.g. English “Software Engineer --- Platform and graphics”, French “Ingénieur logiciel --- Plateforme et infographie”); keep breadth (backend, security, cloud, teaching, open source) in body copy without leading with a long CI/CD tool chain.
- When mentioning teaching, lead with the role or outcome and put course identifiers such as LOG8100 in parentheses rather than opening with the course code alone.
- When merging user-supplied French prose into LaTeX, keep tailoring macros (`\RecipientName`, `\RoleTitle`, `\WhyCompany`, `\CompanyName`, `\LetterSubject` where used) and fix typography (spaces around names like uml-mcp, hyphenation, no duplicated opening hooks).
- On static HTML CV pages (`index-en.html` / `index-fr.html`), **omit public cover-letter links** so the page stays PDF- and contact-oriented. For **About**, user may combine profile + education in one bullet (generalist platform/graphics wording, EN/FR parity) and **remove open-source maintainer copy from About** while keeping optional **github-profile-stats** in Contact; OSS credibility may still appear in Selected projects or per-repo star badges.
- For **Tech Stack** on `index-en.html` / `index-fr.html` and `cv-en/latex/skills.tex` / `cv-fr/latex/skills.tex`, keep EN/FR parity; split **CI/CD & Pipelines** from **Cloud / Platform**, **Testing / Quality** from **Observability**, and use separate **Intermediate** / **Intermédiaire** rows per tool when the user corrects level (e.g. Blender, CUDA, OpenCV, C#, Android, Vue, GraphQL, CSS, .NET, Azure DevOps, Terraform, Sentry, Serilog). Confirm HTML-only vs LaTeX sync per task—the user often wants both aligned after HTML changes.
- **Selected projects**: HTML uses collapsible groups (**Personal projects and maintained open source** / **Contributions and collaborative work**, with **Other accepted contributions** for minor OSS); flagship **uml-mcp** card (linked title, ★ 83 badge) with vertical inline SVG (`viewBox` 148×192, step badges 1–4; EN **UML diagram**, FR **Diagramme UML**); keep SVG inline (no Mermaid.js); simple copy (Cursor MCP + ChatGPT Custom GPT link); sync from `assets/uml-mcp-card-flow.svg` and `uml-mcp-card-flow-fr.svg`; no **plantumlapi** in copy; **GraphQuon 2024** links to `https://graphquon.github.io/` (not the Toronto series page); homelab card may lead with **MediaBoxDockerCompose** and secondary **install scripts** link; **project-title** is one linked repo name only (no `· NuGet` / `· upstream` / `· docs` in the title row—extra links in impact or tags).
- **Other accepted contributions** (HTML): keep lean with one `<li>` per secondary repo and EN/FR parity; do not repeat flagship project-card narratives (e.g. ipc-toolkit friction work stays on the ipc-toolkit card); put related work on the owning card (e.g. TrueMap/surfalize on **TrueMapData**) instead of a duplicate list line.
- When updating GitHub profile stars on the index, refresh the optional contact **github-profile-stats** row (contributions, stars, forks) from figures the user supplies; do not add OSS maintainer lines to About unless asked. Repo-level badges (e.g. uml-mcp ★ 83) stay separate from profile totals.

## Learned Workspace Facts

- **LaTeX CVs**: Main files are `cv-en/resume.tex` and `cv-fr/resume.tex` (Russell class in each tree’s `russell.cls`, fonts under `cv-en/fonts/` and `cv-fr/fonts/` with `\fontdir[fonts/]` in those resumes). Section inputs live under `cv-en/latex/` and `cv-fr/latex/`. Detailed compile options: `docs/development/cv-compilation.md`.
- **CV build (Docker)**: From repo root, `python build_cv.py build -l en` or `-l fr`, or `build --all` (optional `--rebuild`, `--clean`, `--move-to-root`, `--parallel`). Requires Docker for that path; local XeLaTeX is `cd cv-en` or `cv-fr` then `latexmk -xelatex resume.tex` or `xelatex resume.tex` (often two passes for references). GitHub Actions (`compile-cv.yml`, `deploy.yml`, `link-check.yml`) use Python **3.14** and current Actions majors—see `docs/development/github-actions.md`. Local CI smoke: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts\test-pipeline-local.ps1` (`-SkipCompile` for deploy-only).
- **Cover letters**: `letters/en/cover-letter.tex` and `letters/fr/cover-letter.tex` use `\documentclass[11pt, a4paper]{../../cv-en/russell}` and `../../cv-fr/russell` respectively; `\fontdir[../../cv-en/fonts/]` or `\fontdir[../../cv-fr/fonts/]`. File headers document PowerShell: `Set-Location letters/en` or `letters/fr`, then `latexmk -xelatex -interaction=nonstopmode cover-letter.tex` (add `-halt-on-error` if desired). Letter sources do not use a bibliography; no biber step is required for the current templates. GitHub Pages deploy does not copy letter PDFs into `_site/letters/`; `compile-cv.yml` may still build them for local tailoring.
- **Letter tailoring**: `\RecipientName`, `\CompanyName`, `\LetterSubject`, `\RoleTitle`; optional `\WhyCompany` (empty omits that paragraph via `\ifdefempty`).
- **Russell letter title**: `\makelettertitle` fails if `\recipient`’s second argument is empty; the repo uses `\recipient{\RecipientName}{\ifdefempty{\CompanyName}{\vphantom{A}}{\CompanyName}}` so the address line is never an empty break.
- **Static HTML CV**: Public entry points at repo root include `index-en.html`, `index-fr.html`, and `index.html` (redirect). Social links page: `linktree/index.html`. **Selected projects** uses grouped collapsible sections plus a lean **Other accepted contributions** list; experience jobs may include **Soft Skills** (EN) / **Compétences relationnelles** (FR) after technical skills. Contact blocks favor a compact **Cal.com** intro call at `https://cal.com/antoine-boucher-dev/30min` with **icon-based** hero and contact buttons (avoid heavy brand logos or inline embeds unless the user asks). Drop third-party iframe previews on project cards when embeds fail (e.g. Lens Studio)—link out instead. GitHub Pages deploy does not copy `assets/` to `_site`—uml-mcp card flow stays **inline SVG** unless deploy is extended. **Tech Stack** uses dedicated Testing/Quality and Observability rows plus CI/CD vs Cloud categories; skills live in `cv-en/latex/skills.tex` and `cv-fr/latex/skills.tex` when PDFs are synced.
- **Certifications (HTML + LaTeX)**: Link AWS CCP and each AWS Cloud Quest track to Credly badge UUIDs; QcES via Sertifier; keep GDPR/RGPD plain text. On HTML, user may prefer **one compact `<li>`** with comma-separated Credly links for all six Cloud Quest tracks rather than six separate bullets. LaTeX uses `cv-en/latex/certifications.tex` and `cv-fr/latex/certifications.tex` (`\input` from `resume.tex`); remove duplicate Credentials row from `skills.tex` when that section exists.
